# 同步了半年的抖音收藏，正文是一段背景音乐

我用一套开源工具，把抖音收藏自动同步成本地的 Obsidian 知识库。大半年下来跑了十几轮，攒了 932 条收藏、300 多篇笔记，一次报错都没出过。

上个月的某个晚上，我随手点开了几篇。

有一篇的正文长这样：

```
🎼你生看。
🎼嗯。。🎼的都荡。The number you dialed is not in service.
```

第二行那句「The number you dialed is not in service」，是语音识别对着一首纯音乐跑出来的东西。

这篇笔记的头部，状态栏写着 `success`。

我又往后翻了几篇。这样的不止一条。

## 这套流程是怎么跑的

采集收藏、用一套规则筛掉娱乐类内容、语音转写、存成 Markdown 笔记，四个环节全自动，跑完不报错就算完事。

这里有个偷懒我认了：跑完之后，我从来没有打开成品看过。

## 收藏夹里混着三类东西

翻接口返回和现有代码的时候我才发现，抖音的「收藏」根本不是一堆视频。按正文存在哪，它至少分三类：

| 内容形态 | 正文在哪 | 原流程的处理 |
| --- | --- | --- |
| 普通视频 | 音轨里 | 语音识别，正常 |
| 图文帖 | 图片里 | 抓不到，反过来产出噪声 |
| 长文 | 文章接口里 | 抓不到，正文为空 |

这条流水线只认识第一类。

## 第一个坑：视频地址指向的是背景音乐

图文帖没有视频流。它就是几张图，配一首歌。

但接口返回的 `video.play_addr` 字段照样填着一个地址，那是一段 MP3，就是这条帖子的背景音乐。

工具不怀疑这个字段。它按老规矩把 MP3 送进语音识别，ASR 对着一首纯音乐跑了半天，输出上面那种东西，状态随后被标成 `success`。

正文全在图片里，一个字没进来。笔记里反而多了一堆噪声。

顺带说一个判断方法：一条收藏的 `play_url` 如果指向 `obj/ies-music` 并以 `.mp3` 结尾，它几乎一定是图文帖。

## 第二个坑：正文被截断在 499 字

长文这头更安静。

这类内容的正文确实存在，放在 `article_info.article_content` 里，收藏列表接口也会返给你，只是被截断在 499 个字符。

499 字够你看个开头，也够你以为全文就到这了。完整正文需要换一个接口才拿得到。列表接口返回的那一份看起来完全正常，没有截断标记，也没有警告。

## 补上两条通道

定位清楚之后方案很直接：给这条流水线补两条它从来没长出来的通道。

采集时多取一个 `item.images` 字段，把图片送去视觉模型做 OCR；认出长文的 `article_id`，改走 `aweme/detail` 接口取完整正文。

一共动了 4 个文件，四百多行。

图片这一步踩了个模型的坑。我一开始用的专门的文档 OCR 模型 PaddleOCR-VL-1.5，它在社交截图这种图上会反复退化：输出一长串 `0000`，或者一堆 emoji，一直吐到把 token 撑满才停。

换成通用视觉模型 Qwen3-VL-30B-A3B 之后就干净了，正文、楼中楼的评论、表格结构都能还原。

专用模型是在理想场景里专用，贴吧截图和手机截图不是理想场景。

笔记里的样子也随之变了：图文帖会多出一段「图片文字 (OCR)」，逐图列出识别结果；长文会多出一段「文章正文」，保留抖音原文的 Markdown 格式。

## 跑完之后

比「能识别」更要紧的是，这两条通道接进了主同步管线。以后每次同步自动分流：有图的走 OCR，有文章的直接取正文（不消耗 API 额度），都没有才走语音识别。

实测数据：

| 指标 | 数值 |
| --- | --- |
| 收藏总数 | 932 条 |
| 图文帖 | 154 条（其中 122 条已产出 OCR 正文） |
| 长文 | 38 条（补回 35 条） |
| 长文正文合计 | 136,850 字 |
| 知识库笔记 | 306 条 → 366 条 |

最费劲的一条是 100 张图的贴吧长帖。抖音给它的 caption 只有 22 个字的 hashtag，正文全在图里，OCR 出 24,533 字，连楼中楼的回帖都抽了出来。帖子里讲的是流浪汉的江湖，最后一张图是楼主替一位老人还了 260 块钱的账。

还有一批是长文。字数最多的一条是「数字生命卡兹克」写的 Codex 教程，14,948 字；作者里还有一位叫「生信数据人」。

取样验证的时候跑了 6 条图文帖、145 张图，端到端 6 分 57 秒，平均每张 2.9 秒。

顺带查出另一件事。当初筛收藏我用过「去掉娱乐类」的口径，连坐误伤了一批：81 条图文帖从来没进过库，其中 49 条是正经的知识内容。它们从头到尾没被处理过一次。

## 这个病，我在生信里见过

跑过生信流程的人对这套东西有肌肉记忆。

六小时的比对，日志从第一行绿到最后一行，比对率 99%。你关掉终端去做下游分析。三周后才发现，有一半的 reads 比对到了载体序列上。

工具没坏，参数没写错，流程也没崩。它只是没有告诉你，有哪些事它压根没做。

现在我多了一个很土的习惯：不管跑什么自动化，都随机点开几个成品，亲眼看一下。这一次，就是这一眼翻出了那 154 条。
