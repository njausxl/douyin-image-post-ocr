# 932 条收藏，差点丢在一个「成功」里

有些失败是无声的。

它不报错，不打日志，不会在任何地方标红。它甚至会在最后，干净利落地给你一个 `success`。

等你发现的时候，大半年已经过去了。

## 一、点开第三篇笔记的时候，我停了下来

我用一套开源工具，把抖音收藏夹自动同步成本地的 Obsidian 知识库。流程很朴素：采集收藏、筛掉没用的、语音转写、存成 Markdown 笔记。

看到有用的内容随手收藏，想起来的时候跑一次同步。大半年下来，攒了 932 条收藏、300 多篇笔记，一直觉得这套流程运转得挺好。

直到某天夜里，我随机点开了几篇。正文是这样的：

```
🎼你生看。
🎼嗯。。🎼的都荡。The number you dialed is not in service.
```

而它头顶的状态栏，赫然写着 `success`。

## 二、如果你跑过生信流程，这一幕你一定眼熟

跑了六个小时的比对，日志从头绿到尾，比对率 99%。你满意地关掉终端，去做下游分析。

三周后才发现，里面有一半的 reads，比对到了载体序列上。

工具没坏，参数没写错，流程也没崩。

真正的问题是：它没有告诉你，有哪些事它压根没干。

自动化最大的风险，从来不是报错。报错是友善的，它会拦住你。真正可怕的是那种一路绿灯、把错误结果稳稳交付给你的沉默。

会拦住你的失败，都还不算失败。

## 三、收藏夹里，其实混着三类东西

翻了一圈接口返回和已有代码，我才明白问题出在哪。

抖音的收藏，并不是「一堆视频」。按内容形态，它至少分三种：

| 内容类型 | 正文藏在哪 | 原来的处理 |
| --- | --- | --- |
| 普通视频 | 音轨里 | 语音识别，正常 |
| 图文帖 | 图片里 | 完全丢失 |
| 长文 | 文章接口里 | 完全丢失 |

而这条流水线只认识第一类。对后两类，它不但抓不到正文，还会给出一个错误的成功信号。

## 四、第一个坑：那个「视频地址」，指向的是背景音乐

图文帖根本没有视频流。它就是几张图片，配一段音乐。

但接口里 `video.play_addr` 这个字段，照样填了一个地址。那是一段 MP3，是这条帖子的背景音乐。

工具不知道这件事，老老实实把这段 MP3 送去了语音识别。ASR 对着纯音乐跑了半天，于是产出了上面那种似是而非的文字。

然后，它把状态标成了 `success`。

正文全在图片里，一个字都没抓到；笔记里反而多了一堆噪声。

## 五、第二个坑：正文被截断在 499 字

长文这一头更隐蔽。

这类内容的正文确实存在，就放在 `article_info.article_content` 里。看起来一切正常。

但收藏列表接口返回的那一份，被截断在 499 个字符。

499 字，刚好够你看个开头，刚好够你以为自己已经拿到了全文。真正的完整正文，得走另一个接口才能取到。

## 六、补两条通道

问题定位清楚，方案也就清楚了：给这条流水线补上两条它从来没有过的通道。

采集时多取一个 `item.images` 字段，把图片交给视觉模型做 OCR；识别出长文的 `article_id`，改走 `aweme/detail` 接口取完整正文。

一共动了 4 个文件、400 多行代码。

这里还踩了一个模型的坑。一开始我用的是专门的 OCR 模型 PaddleOCR-VL-1.5，结果它在社交截图这种场景上反复退化——输出一长串 0000，或者一堆 emoji，直到把 token 撞满为止。

换成通用的视觉模型 Qwen3-VL-30B-A3B 之后，一下就干净了：正文、楼中楼评论、表格结构，全都能还原出来。

别迷信「专用模型」。专用，是在理想场景里专用，而社交截图显然不是理想场景。

## 七、跑完之后

最关键的改动，其实不是「能识别」，而是接进了主同步管线。以后每次同步会自动分流：

- 有图片的，走 OCR
- 有文章的，直接取正文，零 API 成本
- 都没有的，照旧走语音识别

实测结果：

| 指标 | 数值 |
| --- | --- |
| 收藏总数 | 932 条 |
| 其中图文帖 | 154 条 |
| 其中长文 | 38 条 |
| 知识库笔记 | 306 条 → 366 条 |
| 补回的正文 | 约 24 万字 |

最大的一条，是 100 张图的贴吧长帖。OCR 还原出了 24533 字，连楼中楼的评论都一条没落。

顺带还捞出另一件事：当初筛选收藏时，我用过「去掉娱乐类」的口径，结果连坐误伤了一批。有 81 条图文帖从来没进过库，其中 49 条其实是正经的知识内容。

它们就这样安安静静躺在收藏夹里，从头到尾没被处理过一次。

## 八、真正的教训

这件事的本质，是一个字段语义的误判。

工具以为所有收藏都有一条「视频地址 + 音轨」，但抖音的内容形态早就不是这样了。图文帖的正文在图片里，长文的正文在文章接口里，两者都不在音轨里。

但比这更值得记住的，是另一件事：

一条流程显示成功，不代表它做成了。

这个道理，在生信里尤其常见。日志全绿、比对率 99%、pipeline 正常退出——这些都不是结论，它们只说明「没有崩」。

真正危险的问题不会让流程崩。它只会安静地、一路绿灯地，把错误的结果交付到你手上。

所以，如果你也在跑任何自动化流程，不管是对比、注释，还是这种收藏整理，我都建议你做一件很朴素的事：

随机点开几个成品，亲眼看看。
